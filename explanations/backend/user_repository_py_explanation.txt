# User Repository — Database User Creation and Lookup

## 1. Repository ka purpose

`backend/app/repositories/user_repository.py` database operations handle karti hai.

Is file mein do functions hain:

1. `get_user_by_email()` — email ke through existing user find karna.
2. `create_user()` — database mein naya user insert karna aur uski public details return karna.

Repository ka kaam SQL queries aur database connections handle karna hai. Password hashing aur registration ke business rules service layer mein handle honge.

## 2. Imports

```python
from typing import Any
```

`Any` typing helper hai. Hum `dict[str, Any]` se indicate karte hain ki dictionary ki keys strings hain, jabki values alag-alag Python types ki ho sakti hain.

Example: user dictionary mein `id` integer, `email` string aur `is_active` boolean ho sakta hai.

```python
from backend.app.db.connection import get_db_connection
```

Ye hamare database connection module se function import karta hai.

Isse repository ko har function mein connection settings dobara likhne ki zaroorat nahi hoti.

## 3. `get_user_by_email()` function

```python
def get_user_by_email(email: str) -> dict[str, Any] | None:
```

- `def` function define karta hai.
- `email: str` batata hai ki email string expected hai.
- `dict[str, Any]` ka matlab hai user details ki dictionary.
- `| None` indicate karta hai ki user na milne par function `None` return kar sakta hai.

Ye union type syntax Python 3.10 aur uske baad ke versions mein supported hai.

```python
connection = get_db_connection()
```

Database connection create hota hai.

```python
cursor = connection.cursor(dictionary=True)
```

Cursor SQL statements execute karta hai. `dictionary=True` ke saath fetched rows dictionary format mein milti hain, jisse columns ko unke naam se access kiya ja sakta hai.

```python
cursor.execute(
    """
    SELECT id, full_name, email, password_hash,
           role, is_active, created_at, updated_at
    FROM users
    WHERE email = %s
    LIMIT 1
    """,
    (email,),
)
```

Is query mein:

- `SELECT` required columns retrieve karta hai.
- `FROM users` batata hai ki data `users` table se aayega.
- `WHERE email = %s` matching email select karta hai.
- `LIMIT 1` maximum ek matching row return karne ke liye hai.
- `(email,)` one-element tuple hai jo query parameter supply karta hai.

Parameterized query values ko SQL statement se alag pass karti hai. Isliye user input ko string concatenation se SQL mein jodne ki zaroorat nahi hoti.

`password_hash` yahan select hota hai kyunki future authentication logic ko password verification ke liye stored hash chahiye hoga. Is dictionary ko directly public API response mein expose nahi karna chahiye.

```python
return cursor.fetchone()
```

`fetchone()` ek matching row return karta hai. Agar koi row nahi milti, toh `None` return hota hai.

```python
finally:
    cursor.close()
```

`finally` cleanup ke liye use hota hai. Normal execution ho ya exception, cursor ko close karne ki koshish hoti hai.

```python
finally:
    connection.close()
```

Database connection ko close kiya jata hai, taaki connection unnecessarily open na rahe.

## 4. `create_user()` function

```python
def create_user(
    full_name: str,
    email: str,
    password_hash: str,
) -> dict[str, Any]:
```

Ye function teen values leta hai:

- `full_name`: user ka naam.
- `email`: validated email address.
- `password_hash`: pehle se hashed password.

Function plain-text password accept nahi karta. Service layer ko pehle `hash_password()` call karna chahiye.

```python
connection = get_db_connection()
```

Naya database connection create hota hai.

```python
cursor = connection.cursor(dictionary=True)
```

Cursor insert aur select queries execute karega. Dictionary mode se selected user record dictionary ke form mein milta hai.

```python
cursor.execute(
    """
    INSERT INTO users (full_name, email, password_hash)
    VALUES (%s, %s, %s)
    """,
    (full_name, email, password_hash),
)
```

`INSERT INTO` naya record create karta hai.

Is query mein sirf teen columns supply kiye gaye hain. Database ke defaults ke according `role` default `student` aur `is_active` default `1` hoga.

`%s` placeholders parameterized values ke liye hain. Values ko manually SQL string mein concatenate nahi kiya jata.

Database ka unique email constraint duplicate email ko prevent karta hai.

```python
user_id = cursor.lastrowid
```

`lastrowid` newly inserted record ka generated ID deta hai. Hamare `users.id` column mein `AUTO_INCREMENT` enabled hai.

```python
connection.commit()
```

`commit()` current transaction ke changes save karta hai. Iske baad insertion database mein persist ho jata hai.

```python
cursor.execute(
    """
    SELECT id, full_name, email, role,
           is_active, created_at, updated_at
    FROM users
    WHERE id = %s
    """,
    (user_id,),
)
```

Insert ke baad hum generated ID se record retrieve karte hain. Is query mein `password_hash` intentionally include nahi kiya gaya.

```python
user = cursor.fetchone()
```

Inserted user ki row dictionary ke form mein fetch hoti hai.

```python
if user is None:
    raise RuntimeError(
        "User was inserted but could not be retrieved."
    )
```

Agar expected record retrieve nahi hota, toh function runtime error raise karta hai. Ye unusual database condition ko silently ignore karne se better hai.

```python
return user
```

Public user fields wali dictionary calling function ko return hoti hai.

## 5. Exception handling aur transaction

```python
except Exception:
    connection.rollback()
    raise
```

Agar insertion ya retrieval ke dauran exception aata hai, toh rollback attempt hota hai aur original exception dobara raise hota hai.

`raise` error ko hide nahi karta; caller ko error handling ka mauka deta hai.

Is implementation mein insertion ke baad commit ho chuka hota hai. Isliye agar commit ke baad retrieval fail hota hai, rollback committed insertion ko undo nahi kar sakta. Aise case mein record database mein reh sakta hai, bhale hi function error return kare.

```python
finally:
    cursor.close()
```

Cursor cleanup hota hai.

```python
finally:
    connection.close()
```

Database connection close hota hai.

## 6. Important security points

- Password ko hash karne ke baad hi `create_user()` ko pass karo.
- `get_user_by_email()` ka complete result public response mein return mat karo, kyunki usmein `password_hash` hai.
- Email validation schema mein honi chahiye.
- Duplicate email ko registration service mein safely handle karna hoga.
- Database errors mein passwords, hashes ya credentials logs mein expose nahi karne chahiye.
