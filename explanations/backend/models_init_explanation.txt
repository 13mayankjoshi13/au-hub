AU HUB — MODELS PACKAGE KI EXPLANATION

File path: backend/app/models/__init__.py

==================================================
1. MODEL KYA HOTA HAI?
==================================================

Software development mein model ek aisa component hota hai jo kisi data entity ko represent karta hai.

AU Hub mein future examples:
- User
- Course
- Quiz
- LearningResource

Database ORM (Object-Relational Mapper) use karne par model class ko database table ke saath map kiya ja sakta hai.

Example ke liye, User model ek user record ko represent kar sakta hai.

Important: Har project mein "model" ka exact meaning architecture par depend karta hai. Hum AU Hub mein database models ke liye is folder ka use plan kar rahe hain.

==================================================
2. __init__.py KA KYA KAAM HAI?
==================================================

`__init__.py` Python package ki initialization file hai.

Is file ko empty rakhna valid hai. Ye khud User, Course ya Quiz model create nahi karti.

Actual model classes baad mein separate files mein define hongi.

==================================================
3. MODEL AUR SCHEMA MEIN DIFFERENCE
==================================================

Schema:
API request ya response ke expected data structure aur validation ko define kar sakta hai.

Database model:
ORM architecture mein database table aur uske records ko represent kar sakta hai.

Example:

Signup schema decide kar sakta hai ki request mein valid email aur required fields hon.

User database model define kar sakta hai ki user ka data database mein kis structure mein store hoga.

Dono related hain, lekin dono ka purpose same nahi hai.

==================================================
4. MODEL AUR DATABASE TABLE KA RELATION
==================================================

ORM use karne par model class ko database table ke saath map kiya ja sakta hai.

Example ke liye, future User model mein id, email aur full_name jaise fields ho sakte hain.

Actual table structure, constraints aur relationships ko database design aur migrations ke through manage kiya ja sakta hai.

Sirf Python model file banane se zaroori nahi ki database table automatically create ho jaaye. Ye chosen ORM aur migration/configuration process par depend karta hai.

==================================================
5. FUTURE FILE STRUCTURE
==================================================

Possible future structure:

models/

`user.py` user-related database model rakh sakti hai.

`course.py` course-related model rakh sakti hai.

`quiz.py` quiz-related model rakh sakti hai.

Ye future plan hai; abhi in files ko create nahi karna.

==================================================
6. IMPORTANT DESIGN POINT
==================================================

Model mein database-related fields aur relationships define ho sakte hain, lekin poori business logic ko model file mein rakhna zaroori nahi.

Project grow hone par database models, schemas, repositories aur services ki responsibilities ko clearly separate rakhenge.

==================================================

==================================================
