
AU HUB — CONFIGURATION FILE KI COMPLETE EXPLANATION

1. CONFIGURATION FILE KYA HOTI HAI?

Configuration file mein application ki settings rakhi jaati hain.

AU Hub mein humein application ka naam, version, API prefix aur MySQL
database ki connection settings chahiye hongi.

In settings ko ek jagah rakhne se unhe manage karna easier hota hai.
Agar future mein database host ya port change hota hai, toh hum settings
ko central configuration file ya environment variables se update kar sakte hain.

File path:
backend/app/core/config.py

2. import os

Code:
import os

Python ka os module operating system ke saath interact karne ki
functionality provide karta hai.

Is file mein hum os.getenv() use karenge, jo operating system se
environment variable ki value read karta hai.

Environment variable ek setting hoti hai jo application ke code ke
bahar define ki ja sakti hai.

Example:
AU_HUB_DB_HOST=127.0.0.1

Isse database host ki setting Python source code se alag rakhi ja sakti hai.

3. APP_NAME

Code:
APP_NAME = "AU Hub"

Yahan APP_NAME naam ka variable create kiya gaya hai.

Variable ek naam hota hai jiske through hum kisi value ko access karte hain.

"AU Hub" ek string hai, yaani text value.

Application ka naam future mein logs, API documentation ya doosri
settings mein reuse kiya ja sakta hai.

Abhi ye variable tabhi effect karega jab koi code ise import karke use karega.

4. APP_VERSION

Code:
APP_VERSION = "0.1.0"

Ye application version store karta hai.

Version number ka ek common format MAJOR.MINOR.PATCH hota hai.

0.1.0 ek initial development version ko represent kar sakta hai.
Iska exact meaning project ki versioning policy par depend karega.

Version ko string rakha gaya hai, kyunki ye version identifier hai,
mathematical number nahi.

5. API_PREFIX

Code:
API_PREFIX = "/api/v1"

Ye future API routes ke liye proposed common prefix hai.

Example:
 /api/v1/students
 /api/v1/resources

Isse API ke version ko route structure mein represent kiya ja sakta hai.

Important:
Sirf API_PREFIX variable define karne se existing routes automatically
change nahi honge. Jab hum ise FastAPI routers mein use karenge,
tab iska practical effect hoga.

6. DB_HOST

Code:
DB_HOST = os.getenv("AU_HUB_DB_HOST", "127.0.0.1")

os.getenv() do important arguments le raha hai.

Pehla argument:
"AU_HUB_DB_HOST"

Ye environment variable ka naam hai jahan se host ki setting read hogi.

Doosra argument:
"127.0.0.1"

Ye default value hai. Agar AU_HUB_DB_HOST set nahi hai, toh application
localhost address use karegi.

127.0.0.1 ka matlab current computer hai.

Ye tab suitable hai jab MySQL isi computer par run kar raha ho.
Remote database ke case mein host alag ho sakta hai.

7. DB_PORT

Code:
DB_PORT = int(os.getenv("AU_HUB_DB_PORT", "3306"))

MySQL ka common default port 3306 hai.

os.getenv() environment variable ki value string ke roop mein deta hai.

Isliye int() us string ko integer mein convert karta hai.

Example:
"3306" -> 3306

Agar port ki environment variable mein invalid text diya gaya, toh
int() ValueError raise karega. Is code mein custom validation abhi
implement nahi ki gayi hai.

8. DB_USER

Code:
DB_USER = os.getenv("AU_HUB_DB_USER", "root")

Ye MySQL username read karta hai.

Local development mein root account use ho sakta hai, agar tumhare
MySQL installation mein ye account available ho.

Lekin production application ke liye dedicated database user banana
better hai, jise sirf required database aur operations ki permissions hon.

Root account ko application mein use karna unnecessary privilege risk
create kar sakta hai.

9. DB_PASSWORD

Code:
DB_PASSWORD = os.getenv("AU_HUB_DB_PASSWORD", "")

Ye database password environment variable se read karta hai.

Agar variable set nahi hai, toh default empty string use hogi.

Important security point:
Empty password ka matlab secure authentication nahi hai.
Ye default sirf local development configuration ke liye hai.

Real database password ko Python file, Git commit ya public GitHub
repository mein hardcode nahi karna chahiye.

Is code mein .env file automatically load nahi hoti.
Agar hum .env file use karna chahenge, toh uske liye suitable loading
mechanism separately configure karna hoga.

10. DB_NAME

Code:
DB_NAME = os.getenv("AU_HUB_DB_NAME", "au_hub")

Ye database ka naam read karta hai.

Default naam "au_hub" rakha gaya hai.

Lekin is naam ko configuration mein likhne se database create nahi hota.
MySQL server par database ko separately create karna hoga.

Agar actual database ka naam different hai, toh environment variable
ke through correct naam provide karna hoga.

11. ENVIRONMENT VARIABLES KYON USE KARTE HAIN?

Maan lo development machine par database ka naam au_hub hai, lekin
testing server par database ka naam alag hai.

Agar settings source code mein hardcode hongi, toh environment change
karne ke liye code edit karna pad sakta hai.

Environment variables se hum same code ko different environments mein
different settings ke saath run kar sakte hain.

Lekin environment variables ko bhi carefully manage karna chahiye.
Unhe logs mein print karna ya accidentally expose karna avoid karein.

12. KYA IS FILE SE DATABASE CONNECT HO JATA HAI?

Nahi.

Ye file sirf configuration values define karti hai.

Abhi:
- MySQL connection open nahi hota.
- Database exist karta hai ya nahi, ye check nahi hota.
- Username/password verify nahi hote.
- Koi SQL query execute nahi hoti.
- Database connection close karne ka code nahi hai.

Connection establish karne ke liye MySQL driver aur separate database
connection logic implement karni hogi.

13. QUICK REVISION

Q1. os.getenv() kya karta hai?
Answer: Environment variable ki value read karta hai, aur variable
missing ho toh optional default value return kar sakta hai.

Q2. int() kyun use hua?
Answer: Port ki string value ko integer mein convert karne ke liye.

Q3. Kya API_PREFIX define karne se routes automatically change hote hain?
Answer: Nahi. Is variable ko routing configuration mein use karna hoga.

Q4. Kya DB_NAME define karne se MySQL database create hota hai?
Answer: Nahi.

Q5. Kya DB_PASSWORD ko GitHub par commit karna chahiye?
Answer: Nahi. Real credentials ko source code aur public repository se
bahar rakhna chahiye.

Q6. Kya ye configuration database connection test karti hai?
Answer: Nahi. Ye sirf configuration values prepare karti hai.

FINAL SUMMARY

config.py AU Hub ki application aur database settings ko centralize karti hai.

Environment variables ki help se database settings ko source code se
alag rakha ja sakta hai. Lekin actual connection, validation aur database
security ke liye humein additional implementation karni hogi.
