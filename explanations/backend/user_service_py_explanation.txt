# User Service — Registration and Login Verification

## 1. Service layer ka role

`backend/app/services/user_service.py` authentication ke business rules handle karti hai.

Is file mein:
- Password hashing
- Password verification
- User registration
- Duplicate email handling
- Login credentials verification
- Inactive account rejection

Repository SQL aur database access handle karti hai. Service decide karti hai ki data ko kaise use karna hai aur kaunse business rules apply hone chahiye.

`IntegrityError` database constraint violations ko identify karne ke liye use hota hai, jaise duplicate email.

## 3. Password hasher

```python
password_hasher = PasswordHash.recommended()
```

Ye `pwdlib` ki recommended password-hashing configuration ka object create karta hai.

```python
def hash_password(password: str) -> str:
    return password_hasher.hash(password)
```

Registration ke waqt plain-text password ko hash kiya jata hai. Database mein original password store nahi hota.

```python
def verify_password(
    plain_password: str,
    hashed_password: str,
) -> bool:
    return password_hasher.verify(plain_password, hashed_password)
```

Login ke waqt entered password ko stored hash ke against verify kiya jata hai. Original password ko hash se recover nahi kiya jata.

Malformed stored hash par verification exception raise kar sakta hai. Production authentication layer mein unexpected verification errors ko safely handle karna zaroori hai.

## 4. Custom exceptions

```python
class EmailAlreadyRegisteredError(Exception):
    """Raised when an email address is already registered."""
```

Ye registration ke duplicate-email case ko represent karta hai.

```python
class InvalidCredentialsError(Exception):
    """Raised when login credentials are invalid."""
```

Ye login failure ko represent karta hai. Route is exception ko baad mein HTTP `401 Unauthorized` response mein convert karega.

## 5. Registration function

```python
def register_user(user_data: UserCreate) -> UserResponse:
```

Ye function validated registration data accept karta hai.

```python
existing_user = get_user_by_email(str(user_data.email))
```

Database mein email check hota hai.

```python
if existing_user is not None:
    raise EmailAlreadyRegisteredError(
        "An account with this email already exists."
    )
```

Email pehle se registered ho, toh registration stop hota hai.

```python
hashed_password = hash_password(user_data.password)
```

Password ka secure hash create hota hai.

```python
created_user = create_user(
    full_name=user_data.full_name,
    email=str(user_data.email),
    password_hash=hashed_password,
)
```

Repository ko plain-text password ki jagah hash diya jata hai.

`IntegrityError` ke case mein MySQL error `1062` duplicate-key error identify karta hai. Database ka unique email constraint simultaneous registration requests ke against bhi protection provide karta hai.

```python
return UserResponse.model_validate(created_user)
```

Public user fields response schema mein convert hote hain. Password hash response mein include nahi hota.

## 6. `authenticate_user()` function

```python
def authenticate_user(
    email: str,
    password: str,
) -> UserResponse:
```

Ye function login ke liye email aur entered password accept karta hai.

```python
user = get_user_by_email(email)
```

Repository database se matching user retrieve karti hai. Is query mein password hash bhi aata hai, jise public API response mein expose nahi karna chahiye.

```python
if user is None:
    raise InvalidCredentialsError("Invalid email or password.")
```

Email ka account nahi mila, toh login reject hota hai.

```python
if not user["is_active"]:
    raise InvalidCredentialsError("Invalid email or password.")
```

Agar account inactive hai, toh login reject hota hai. Database ka `is_active` field `0` ya `1` ke form mein aa sakta hai; Python mein `0` false aur `1` true hota hai.

```python
if not verify_password(password, user["password_hash"]):
    raise InvalidCredentialsError("Invalid email or password.")
```

Entered password stored hash se match nahi karta, toh login reject hota hai.

Wrong email aur wrong password ke liye same message use karne se account existence reveal karne ka risk kam hota hai.

```python
return UserResponse.model_validate(user)
```

Credentials valid hone par public user details return hoti hain. `UserResponse` mein `password_hash` field defined nahi hai, isliye hash public response mein return nahi hota.

## 7. Important limitations

Ye function credentials verify karta hai; abhi login session ya access token issue nahi karta.

Next step mein API route is function ko call karega aur `InvalidCredentialsError` ko HTTP `401 Unauthorized` response mein convert karega.

Production login ke liye:
- HTTPS use karo.
- Login attempts par rate limiting lagao.
- Unexpected hashing errors ko safely handle karo.
- Passwords aur password hashes logs mein mat likho.
- Token/session security ko separately implement karo.
