# User Service — Registration Business Logic

## 1. Service layer ka purpose

`backend/app/services/user_service.py` registration ke business rules handle karti hai.

Is file mein:
- Password hashing aur verification functions hain.
- Existing email check hota hai.
- Password hash karke repository ko diya jata hai.
- Duplicate email condition handle hoti hai.
- Public user response return hota hai.

Repository SQL aur database operations handle karti hai. Service decide karti hai ki registration kis order mein aur kin rules ke according execute hoga.

## 3. Password hasher

```python
password_hasher = PasswordHash.recommended()
```

Ye recommended password-hashing configuration ka object create karta hai.

```python
def hash_password(password: str) -> str:
    return password_hasher.hash(password)
```

Ye function plain-text password ko encoded password hash mein convert karta hai.

Database mein original password store nahi karna chahiye.

```python
def verify_password(
    plain_password: str,
    hashed_password: str,
) -> bool:
    return password_hasher.verify(plain_password, hashed_password)
```

Ye function entered password ko stored hash ke against verify karta hai. Login flow mein iska use hoga.

Malformed stored hashes ke liye verification exception raise kar sakta hai. Authentication layer ko aise errors safely handle karne honge.

## 4. Duplicate-email exception

```python
class EmailAlreadyRegisteredError(Exception):
    """Raised when an email address is already registered."""
```

Hum ek custom exception define karte hain. Jab email pehle se registered ho, service ye exception raise kar sakti hai.

Custom exception ka benefit ye hai ki API layer duplicate registration ko database error ki jagah understandable client response mein convert kar sakti hai.

## 6. Password hash aur database insertion

```python
hashed_password = hash_password(user_data.password)
```

Original password ko hash kiya jata hai.

```python
created_user = create_user(
    full_name=user_data.full_name,
    email=str(user_data.email),
    password_hash=hashed_password,
)
```

Repository ko naam, email aur **hashed password** diya jata hai.

Plain-text password database repository ko pass nahi kiya jata.

## 7. Database duplicate-key handling

```python
except IntegrityError as error:
```

Database insertion ke waqt integrity-related error aane par ye block execute hota hai.

```python
if error.errno == 1062:
```

MySQL error code `1062` duplicate-key error ko identify karta hai.

Pehle email check karna helpful hai, lekin do simultaneous registration requests dono ko initial check par email unavailable na mile, aisa ho sakta hai. Database ka `UNIQUE` constraint final protection provide karta hai.

```python
raise EmailAlreadyRegisteredError(
    "An account with this email already exists."
) from error
```

Duplicate-key error ko service ke custom exception mein convert kiya jata hai. `from error` original exception ko cause ke roop mein preserve karta hai.

```python
raise
```

Agar error duplicate-key error nahi hai, toh use hide nahi karte. Unexpected database failures ko API layer safely handle karegi.

## 8. Public response

```python
return UserResponse.model_validate(created_user)
```

Database se mila record `UserResponse` schema mein convert hota hai.

Public response mein `id`, `full_name`, `email`, `role` aur `is_active` jaise fields hote hain. `password_hash` return nahi hota.

`model_validate()` Pydantic v2 ka method hai. Isliye project mein Pydantic v2 installed hona chahiye.

## 9. Important limitations

- Ye service abhi khud HTTP endpoint nahi hai.
- API route ko `EmailAlreadyRegisteredError` ko HTTP `409 Conflict` response mein convert karna hoga.
- Unexpected database errors ko controlled HTTP error mein handle karna hoga.
- Password hashing ke baad bhi HTTPS, secure secrets management, rate limiting aur account-abuse protection zaroori hain.
- Service ko database ke saath integration test karna abhi baaki hai.
